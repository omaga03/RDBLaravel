# ส่วนที่ 1: เล่มที่ 1 คู่มือการใช้งานระบบหน้าบ้าน (Volume 1: Frontend Public User Manual)
> **กลุ่มเป้าหมาย**: ประชาชนทั่วไป, คณาจารย์, นักศึกษา, ภาคีเครือข่าย, และหน่วยงานภาครัฐ/เอกชน

### บทที่ 1: ภาพรวมระบบและการนำทาง (System Overview & Interface Navigation)
* **1.1 แนะนำระบบฐานข้อมูลงานวิจัย มรภ.เพชรบูรณ์**: วัตถุประสงค์ พันธกิจ และขอบเขตการให้บริการสารสนเทศวิจัย
* **1.2 โครงสร้างหน้าจอหลัก (Portal Layout Walkthrough)**:
  * แถบเมนูด้านบน (Main Navigation Bar)
  * แบนเนอร์ค้นหาหลัก (Hero Search Section)
  * ส่วนสรุปสถิติด้านงานวิจัย (Key Research Metrics & Counter Cards)
  * ผลงานวิจัยและบทความตีพิมพ์เผยแพร่ล่าสุด (Recent Publications Feed)
* **1.3 การเปลี่ยนธีมหน้าจอ (Dark Mode / Light Mode Switcher)**:
  * การสลับโหมดกลางวัน (Daylight Editorial Slate) และโหมดกลางคืน (Carbon-Navy Night Reading)
  * การบันทึกการตั้งค่าธีมลง Local Storage อัตโนมัติ

### บทที่ 2: การสืบค้นข้อมูลวิจัยอัจฉริยะ (Smart Search & Dynamic Filtering)
* **2.1 การค้นหาด่วนด้วยคำสำคัญ (Global Quick Search)**:
  * การสืบค้นชื่อโครงการ, ชื่องานวิจัย, ชื่อบทความ, และคำสำคัญ (Keywords)
* **2.2 ตัวกรองตามปีงบประมาณ พ.ศ. (Fiscal Year Filtering)**:
  * การเลือกปีงบประมาณ พ.ศ. จาก Dropdown เพื่อดูผลงานและสถิติจำเพาะปี
* **2.3 ระบบค้นหาขั้นสูงแบบกลุ่มคำ (Multi-Keyword Search Logic)**:
  * โหมด "ค้นหาตรงทุกคำ (Match All / AND)"
  * โหมด "ค้นหาตรงบางคำ (Match Any / OR)"
* **2.4 ระบบตัดคำนำหน้าชื่อภาษาไทยอัตโนมัติ (Thai Title Prefix Normalization)**:
  * การพิมพ์ค้นหาชื่อนักวิจัยโดยมีหรือไม่มีคำนำหน้า (เช่น นาย, นาง, นางสาว, ดร., ผศ., รศ., ศ.)

### บทที่ 3: การใช้งานโมดูลโครงการวิจัย (Research Projects Directory)
* **3.1 หน้ารวมรายการโครงการวิจัย (`/rdbproject`)**:
  * โครงสร้างตารางรายการ, การเรียงลำดับ (Sort by Year/Name), และการแบ่งหน้า (Pagination)
* **3.2 หน้าแสดงรายละเอียดโครงการวิจัย (`/rdbproject/{id}`)**:
  * การแสดงชื่อโครงการภาษาไทยและภาษาอังกฤษ
  * คณะผู้วิจัยและสังกัดหน่วยงาน (Principal Investigator & Co-Researchers)
  * แหล่งทุนสนับสนุนการวิจัยและงบประมาณ (Research Grants & Funding)
  * บทคัดย่อภาษาไทยและบทคัดย่อภาษาอังกฤษ พร้อมปุ่มคัดลอกข้อความด่วน
* **3.3 ระดับการเข้าถึงไฟล์เอกสารวิจัย 3 ระดับ (Document Access & Privacy Policy)**:
  * **กรณีที่ 1: เปิดเผยสาธารณะ (`pro_file_show = 0`)** → แสดงภาพตัวอย่างหน้าแรก `.webp` (Cover Preview), แสดงจำนวนหน้าของเล่มรายงาน, ปุ่มดาวน์โหลดเล่มรายงานฉบับสมบูรณ์ (Full Report PDF)
  * **กรณีที่ 2: ปกปิดเล่มรายงาน (`pro_file_show = 1`)** → แสดงป้ายเตือน "เล่มรายงานวิจัยถูกปกปิด (ไม่สามารถเปิดเผยข้อมูลได้)"
  * **กรณีที่ 3: ฉบับร่าง (`pro_file_show = 2`)** → แสดงป้ายเตือน "เล่มรายงานวิจัยอยู่ในสถานะฉบับร่าง (ยังไม่เผยแพร่)"
* **3.4 การเปิดดูไฟล์บทคัดย่อ (Abstract PDF Viewer)**:
  * การเปิดดูบทคัดย่อแบบ Inline Preview บนเบราว์เซอร์ และการนับสถิติการเข้าชม

### บทที่ 4: การใช้งานโมดูลผลงานตีพิมพ์และงานวิชาการ (Publications Directory)
* **4.1 หน้ารวมรายการบทความตีพิมพ์ (`/rdbpublished`)**:
  * การจำแนกตามประเภทผลงาน: วารสารนานาชาติ (International Journals), วารสารระดับชาติ (National Journals), รายงานสืบเนื่องการประชุมวิชาการ (Proceedings)
  * ฐานข้อมูลที่รองรับการจัดอันดับ: Scopus, Web of Science, TCI กลุ่ม 1, TCI กลุ่ม 2
* **4.2 หน้าแสดงรายละเอียดบทความวิชาการ (`/rdbpublished/{id}`)**:
  * รายชื่อผู้ประพันธ์และผู้ประพันธ์บรรณกิจ (First Author & Corresponding Author)
  * ข้อมูลวารสาร: ชื่อวารสาร, ปีที่ (Volume), ฉบับที่ (Issue), เลขหน้า (Pages), ค่า DOI
  * ภาพหน้าแรกบทความ (.webp) และปุ่มดาวน์โหลดบทความฉบับเต็ม (Full Paper PDF)
* **4.3 ระบบคัดลอกรูปแบบการอ้างอิงวิชาการ (One-Click Citation Formats)**:
  * การใช้งานแถบเลือกรูปแบบการอ้างอิง: **APA 7th Edition**, **IEEE Standard**, **MLA 9th Edition**
  * ปุ่ม "คัดลอกการอ้างอิง (Copy Citation)" พร้อมการแจ้งเตือนแบบ Interactive Toast

### บทที่ 5: การใช้งานโมดูลทรัพย์สินทางปัญญา (Intellectual Property - DIP)
* **5.1 หน้ารายการทรัพย์สินทางปัญญา (`/rdbdip`)**:
  * การจำแนกตามประเภท: สิทธิบัตรการประดิษฐ์, อนุสิทธิบัตร, ลิขสิทธิ์, เครื่องหมายการค้า
* **5.2 การตรวจสอบสถานะคำขอ**:
  * เลขที่คำขอ, วันที่ยื่นคำขอ, วันที่ได้รับการจดทะเบียน (แสดงผลรูปแบบ พ.ศ. เสมอ)
  * รายชื่อผู้ประดิษฐ์และผู้สร้างสรรค์ผลงาน

### บทที่ 6: การใช้งานโมดูลการนำงานวิจัยไปใช้ประโยชน์ (Research Utilizations)
* **6.1 การจำแนกการใช้ประโยชน์ 4 มิติ (`/rdbprojectutilize`)**:
  * 1. การใช้ประโยชน์เชิงพาณิชย์ (Commercial Utilization)
  * 2. การใช้ประโยชน์เชิงนโยบาย (Policy Utilization)
  * 3. การใช้ประโยชน์เชิงชุมชนและสังคม (Community & Social Utilization)
  * 4. การใช้ประโยชน์เชิงวิชาการ (Academic Utilization)
* **6.2 การตรวจสอบผลกระทบและพื้นที่ (Impact & Geo-location)**:
  * หน่วยงานหรือกลุ่มเป้าหมายที่นำผลงานไปใช้
  * พื้นที่นำไปใช้ประโยชน์ (จังหวัด, อำเภอ, ตำบล) พร้อมเอกสารหลักฐานรับรอง

### บทที่ 7: การใช้งานทำเนียบนักวิจัย (Researchers Directory & Academic Portfolio)
* **7.1 ค้นหาประวัตินักวิจัย (`/rdbresearcher`)**:
  * ค้นหาตามชื่อ-สกุล, ตำแหน่งทางวิชาการ (ศ., รศ., ผศ., อ.), และสังกัดคณะ/สถาบัน
* **7.2 แฟ้มผลงานวิจัยของนักวิจัย (Researcher Academic Portfolio)**:
  * ข้อมูลรหัสสากล: **Scopus Author ID** (พร้อมลิงก์ตรงไปยังฐานข้อมูล Elsevier) และ **ORCID iD**
  * รายการโครงการวิจัยที่รับผิดชอบทั้งหมดในฐานข้อมูล
  * รายการบทความตีพิมพ์และทรัพย์สินทางปัญญาทั้งหมดของนักวิจัย

### บทที่ 8: แดชบอร์ดสถิติ ข่าวสารทุนวิจัย และบริการข้อมูลเปิด (Dashboards, News & Open Data APIs)
* **8.1 การอ่านข้อมูลแดชบอร์ดสถิติวิจัย (`/dashboard`)**:
  * แดชบอร์ดโครงการวิจัย, ผลงานตีพิมพ์, ทรัพย์สินทางปัญญา, และการนำไปใช้ประโยชน์
  * การทำความเข้าใจแผนภูมิแท่ง (Bar Chart) และแผนภูมิเส้น (Line Chart) แสดงแนวโน้มรายปี
* **8.2 ศูนย์รวมข่าวสารทุนวิจัยและงานประชุมวิชาการ**:
  * การสืบค้นข่าวทุนวิจัย NRIIS และทุนวิจัยภายใน (`/researchnews`)
  * การสืบค้นงานประชุมวิชาการ วันที่จัดงาน และกำหนดส่งผลงาน (`/researchcoferenceinthai`)
* **8.3 การติดตามข่าวสารและฟีด (News & RSS Subscriptions)**:
  * การรับข้อมูลข่าววิจัยและงานประชุมวิชาการผ่าน RSS Feeds (`/feeds/news`, `/feeds/conferences`)
* **8.4 บริการข้อมูลเปิดสำหรับนักพัฒนา (Open Public REST APIs)**:
  * การเชื่อมต่อข้อมูลข่าวสารผ่าน JSON APIs โดยไม่ต้องใช้ Bearer Token (`/api/v1/news`, `/api/v1/conferences`)

# ส่วนที่ 2: เล่มที่ 2 คู่มือการใช้งานระบบหลังบ้าน (Volume 2: Backend Administrative & Researcher Manual)
> **กลุ่มเป้าหมาย**: นักวิจัย, ผู้ทรงคุณวุฒิประเมินงานวิจัย, เจ้าหน้าที่สถาบันวิจัยฯ, หัวหน้าโครงการ, ผู้ประสานงานคณะ, และผู้ดูแลระบบ

### บทที่ 1: การเข้าสู่ระบบและความปลอดภัย (Authentication & Account Security)
* **1.1 วิธีการเข้าสู่ระบบ (Sign-in Methods)**:
  * การล็อกอินผ่าน Google Workspace มหาวิทยาลัย (Google SSO: `@pcru.ac.th`)
  * การล็อกอินด้วยบัญชี Username และ Password ของระบบเดิม
* **1.2 นโยบายความปลอดภัยของรหัสผ่าน**:
  * ความยาวขั้นต่ำ 8 ตัวอักษร, การจำกัดจำนวนครั้งการล็อกอินผิด (Rate Limiting 5 ครั้ง)
* **1.3 การจัดการโปรไฟล์และการผูกบัญชีนักวิจัย (Researcher Account Linking)**:
  * การเชื่อมโยง User ID กับรหัสนักวิจัย (`researcher_id`) ในฐานข้อมูล

### บทที่ 2: โครงสร้างบทบาทและสิทธิ์การใช้งาน (Role-Based Access Control - RBAC)
* **2.1 ตารางเมทริกซ์สิทธิ์ตามบทบาท (Role Permission Matrix)**:
  * **Super Admin / The Creator**: สิทธิ์เต็มทุกโมดูล, จัดการผู้ใช้, จัดการสิทธิ์ RBAC, ดู Audit Log
  * **Admin / Admin Research**: จัดการโครงการ, งานตีพิมพ์, ทรัพย์สินทางปัญญา, อนุมัติผลงาน
  * **Domain Admins (Admin Project / Admin Published / Admin Dip / Admin Utilize)**: ดูแลเฉพาะโมดูลที่รับผิดชอบ
  * **Faculty Coordinator (ผู้ประสานงานคณะ)**: ตรวจสอบและอนุมัติผลงานเฉพาะภายในคณะตนเอง
  * **Researcher (นักวิจัย)**: บันทึกร่างผลงานตนเอง, ส่งตรวจสอบ, ขอปลดล็อกเพื่อแก้ไข
  * **Reviewer (ผู้ทรงคุณวุฒิ)**: ประเมินเล่มรายงานวิจัยตามที่ได้รับมอบหมาย
* **2.2 การจำลองสิทธิ์ผู้ใช้งาน (User Impersonation Feature)**:
  * ขั้นตอนการกด "Impersonate" เพื่อเข้าดูหน้าจอเสมือนเป็นนักวิจัย (สำหรับการช่วยเหลือ/ตรวจสอบปัญหา)
  * ปุ่ม "Stop Impersonating" เพื่อสลับกลับสู่สิทธิ์ Super Admin ทันที

### บทที่ 3: วงจรชีวิตการส่งร่าง ตรวจสอบ และอนุมัติเปิดเผยผลงาน (Workflow Lifecycle: WF-01 ถึง WF-07)
* **3.1 แผนภาพลำดับขั้นตอน (Workflow State Machine Diagram)**:
  * แสดงความสัมพันธ์: `draft` ➔ `pending_review` ➔ `revision_required` ➔ `published` ➔ `unlock_requested`
* **3.2 ขั้นตอนสำหรับนักวิจัย (Researcher Workflow Guide)**:
  * **ขั้นตอนที่ 1 (WF-01)**: การบันทึกฉบับร่าง (Draft) — ข้อมูลถูกจัดเก็บอย่างปลอดภัย แต่ไม่แสดงหน้าบ้าน
  * **ขั้นตอนที่ 2 (WF-02)**: การกดส่งผลงานเข้าสู่กระบวนการตรวจรับ (**"Submit for Review"**)
  * **ขั้นตอนที่ 3 (WF-04)**: การตรวจสอบข้อเสนอแนะกรณีถูกส่งกลับแก้ไข (**"Revision Required"**) และการส่งตรวจรอบใหม่
  * **ขั้นตอนที่ 4 (WF-06)**: การกดขอปลดล็อกผลงานที่เผยแพร่แล้วเพื่อแก้ไข (**"Request Unlock to Edit"**) พร้อมระบุเหตุผล
* **3.3 ขั้นตอนสำหรับเจ้าหน้าที่และผู้ดูแลระบบ (Admin & Coordinator Workflow Guide)**:
  * **ขั้นตอนที่ 1 (WF-03)**: การจัดการคิวงานตรวจสอบผลงานวิจัย (`/backend/workflow/queue`)
  * **ขั้นตอนที่ 2 (WF-04)**: การส่งกลับแก้ไขพร้อมกรอกหมายเหตุและข้อเสนอแนะเชิงวิชาการ (Remarks)
  * **ขั้นตอนที่ 3 (WF-05)**: การอนุมัติผลงานสู่สาธารณะ (**"Approve & Publish"**) — ปรับ `data_show = 1`, นำขึ้นหน้าบ้านทันที, และสั่งสร้างปก `.webp` อัตโนมัติ
  * **ขั้นตอนที่ 4 (WF-07)**: การอนุมัติคำขอปลดล็อก (**"Approve Unlock"**) เพื่อย้ายผลงานกลับสู่สถานะร่างให้นักวิจัยแก้ไข

### บทที่ 4: การบริหารจัดการโครงการวิจัยขั้นสูง (Advanced Research Project Management)
* **4.1 การสร้างและแก้ไขข้อมูลโครงการวิจัย (`/backend/rdb_project`)**:
  * ข้อมูลทั่วไป: รหัสโครงการ, ปีงบประมาณ พ.ศ., ประเภทโครงการ, ยุทธศาสตร์มหาวิทยาลัย
  * การจัดสรรงบประมาณ: งบประมาณรวม, จำแนกตามหมวดเงินทุน, แหล่งทุนสนับสนุน
  * การเพิ่มคณะผู้วิจัยและสัดส่วนการวิจัย (Research Percentage Attribution)
* **4.2 การจัดการไฟล์เอกสารและระบบตรวจนับหน้าอัตโนมัติ (PDF Engine)**:
  * การอัปโหลดเล่มรายงานวิจัยฉบับสมบูรณ์ (`pro_file`)
  * **การทำงานของ Poppler PDF Page Counting**: บันทึกจำนวนหน้าลง `pro_page_num` อัตโนมัติด้วยความแม่นยำ 99.99%
* **4.3 ระบบสกัดภาพปกหน้าแรกของ PDF เป็น `.webp` (Automatic Cover Generator)**:
  * การทำงานของสถาปัตยกรรม 5-Tier Fallback (`PdfCoverService`)
  * การตรวจสอบภาพปกหน้าแรกในการ์ดแสดงผลโครงการ
* **4.4 การควบคุมการเปิดเผยเอกสารรายงาน (`pro_file_show`)**:
  * การสลับสถานะ "เปิดเผยต่อสาธารณะ (เปิด)", "ปกปิดเล่มรายงาน (ปิด)", "ฉบับร่าง (ร่าง)"

### บทที่ 5: ระบบตรวจประเมินเล่มรายงานวิจัยฉบับสมบูรณ์ (Peer Review Subsystem)
* **5.1 บทบาทและกระบวนการประเมินแบบไม่เปิดเผยชื่อผู้ประเมิน (Single-Blind Review Workflow)**
* **5.2 การออกแบบแบบประเมินและเกณฑ์คะแนน (Dynamic Rubric Form Designer)**:
  * การสร้างชุดเกณฑ์ประเมิน (Evaluation Criteria)
  * การกำหนดคะแนนเต็ม, น้ำหนักคะแนน, และคำอธิบายระดับคุณภาพ (Scale Steps)
* **5.3 การมอบหมายผู้ทรงคุณวุฒิตรวจประเมิน (Reviewer Assignment)**:
  * การเลือกผู้ทรงคุณวุฒิภายในและภายนอกมหาวิทยาลัย
  * การกำหนดวันสิ้นสุดการประเมิน (Due Date)
* **5.4 การบันทึกผลการประเมินของผู้ทรงคุณวุฒิ (Reviewer Evaluation Form)**:
  * การให้คะแนนตามเกณฑ์แบบ Real-time Calculation
  * การแนบไฟล์ข้อเสนอแนะและข้อคิดเห็นเชิงพัฒนา
* **5.5 การสรุปผลคะแนนและการอนุมัติเล่มสมบูรณ์ (Final Report Approval)**:
  * การรวบรวมคะแนนเฉลี่ยจากผู้ทรงคุณวุฒิทุกท่าน
  * การกดอนุมัติเล่มสมบูรณ์ (`approveFinalReport`) ➔ ปรับสถานะโครงการเป็นเสร็จสิ้น และเปิดเผยเอกสารอัตโนมัติ

### บทที่ 6: การบริหารจัดการผลงานตีพิมพ์, ทรัพย์สินทางปัญญา และการใช้ประโยชน์
* **6.1 การจัดการผลงานตีพิมพ์ (`/backend/rdb_published`)**:
  * การบันทึกข้อมูลบทความ, การแม็ปข้อมูลผู้แต่ง (Authors Mapping)
  * การอัปโหลดไฟล์บทความ (Full Paper PDF), การตรวจนับหน้าอัตโนมัติ (`pub_numfile`), และการสร้างปก `.webp`
* **6.2 การจัดการทรัพย์สินทางปัญญา (`/backend/rdb_dip`)**:
  * การบันทึกเลขที่คำขอ, วันที่ยื่นคำขอ, วันที่จดทะเบียน, ไฟล์เอกสารคำขอ
* **6.3 การจัดการการนำไปใช้ประโยชน์ (`/backend/rdbprojectutilize`)**:
  * การเชื่อมโยงกับโครงการวิจัยต้นทาง, การเลือกประเภทการใช้ประโยชน์ 4 ด้าน, การแนบหนังสือรับรองผลกระทบ

### บทที่ 7: การบริหารข้อมูลนักวิจัยและการเชื่อมโยงภายนอก (Researcher & Integration Management)
* **7.1 การจัดการข้อมูลนักวิจัย (`/backend/rdb_researcher`)**:
  * การตรวจสอบความถูกต้องของเลขประจำตัวประชาชน 13 หลักตามมาตรฐานกรมการปกครอง
  * การกำหนดคำนำหน้าชื่อไทย, วุฒิการศึกษา, และสังกัดคณะ/ภาควิชา
* **7.2 การเชื่อมโยง Scopus Author API & ORCID iD**:
  * การระบุ Scopus Author ID และการดึงข้อมูล h-index, Citations, Document Counts
  * การตรวจสอบรูปแบบ ORCID Format (XXXX-XXXX-XXXX-XXXX)

### บทที่ 8: การส่งออกข้อมูลและการเชื่อมต่อคลังปัญญาสถาบัน (Data Export & DSpace SAF Integration)
* **8.1 การส่งออกข้อมูลขนาดใหญ่เป็น CSV/Excel (UTF-8 BOM Streaming)**:
  * การ Export ข้อมูลโครงการวิจัย, ผลงานตีพิมพ์, และนักวิจัย ทั้งระบบ
  * การรับประกันการเปิดไฟล์ใน Microsoft Excel ภาษาไทย 100% ด้วย UTF-8 BOM (`\xEF\xBB\xBF`)
* **8.2 ระบบส่งออกแพ็กเกจคลังปัญญา DSpace (DSpace Simple Archive Format - SAF Export)**:
  * การส่งออกรายโครงการและการส่งออกเป็นกลุ่ม (Batch Export Mode)
  * โครงสร้างไฟล์ ZIP: `dublin_core.xml` (Dublin Core Metadata), `contents` (Manifest File), และไฟล์ PDF เอกสารวิจัย
  * การปรับปรุงสถานะการส่งออก (Export Status Synchronization)

### บทที่ 9: บันทึกประวัติการใช้งานและการตั้งค่าความปลอดภัย (Audit Trail & Security Settings)

  * การจัดการนโยบายการลงทะเบียนผู้ใช้งานใหม่

# ส่วนที่ 3: แผนปฏิบัติการและมาตรฐานการผลิตรูปเล่ม (Production Standards & Milestones)

### 3.1 มาตรฐานการเขียนและการจัดทำรูปเล่ม (Editorial & Formatting Standards)
1. **โทนการเขียน (Tone of Voice)**: ใช้ภาษาทางการเชิงวิชาการ ชัดเจน กระชับ เป็นขั้นเป็นตอน (Step-by-step Instructional Guide)
2. **การจับภาพหน้าจอ (UI Screenshots Standards)**:
   * ทุกภาพต้องมีกรอบสีแดงเน้นจุดคลิก (Bounding Box / Highlight Indicator) พร้อมลูกศรชี้ลำดับ 1, 2, 3
   * ภาพถ่ายจากระบบจริงบนความละเอียด 1920x1080 (FHD) สัดส่วนคมชัด ไม่แตกเบลอ
   * ทำภาพประกอบครอบคลุมทั้ง Light Mode และ Dark Mode ในจุดที่สำคัญ
3. **การใช้กล่องข้อความแจ้งเตือน (Callout Alerts)**:
   * `[คำแนะนำ - TIP]`: เคล็ดลับการใช้งานหรือคีย์ลัด
   * `[ข้อควรระวัง - WARNING]`: ขั้นตอนที่ส่งผลต่อการเผยแพร่ข้อมูลหรือสิทธิ์การเข้าถึง
   * `[สำคัญมาก - IMPORTANT]`: ข้อบังคับทางระเบียบวิจัย หรือนโยบายความปลอดภัย

### 3.2 รูปแบบเอกสารที่ส่งมอบ (Deliverables)
1. **ไฟล์ต้นฉบับเอกสารดิจิทัล (Digital Markdown Docs)**: จัดเก็บในโฟลเดอร์ `docs/manuals/` ของ Repository เพื่อให้อัปเดตตามเวอร์ชันของซอฟต์แวร์ได้ตลอดเวลา
2. **เล่มคู่มือฉบับพิมพ์สมบูรณ์ (Print-Ready PDF)**: จัดหน้าระดับสำนักพิมพ์ (A4, ฟอนต์ Sarabun/Prompt, เลขหน้ามุมขวาบน, สารบัญลิงก์คลิกได้)
3. **แผ่นพับสรุปขั้นตอนเร่งด่วนสำหรับนักวิจัย (Researcher Quick-Start Cheatsheet 2 หน้า A4)**: สรุปเฉพาะขั้นตอน "วิธีสร้างโครงการ -> ส่งตรวจรับ -> ขอเปิดเผยแพร่" ให้อาจารย์ทำตามได้ภายใน 3 นาที

### 3.3 แผนผังและกรอบระยะเวลาการดำเนินงาน (Implementation Timeline)

สัปดาห์ที่ 2: เรียบเรียงเนื้อหาเล่มที่ 1 (Frontend Public Manual) และทดสอบความสอดคล้องกับ UI
